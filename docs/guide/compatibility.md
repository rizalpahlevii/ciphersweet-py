# Compatibility with PHP

ciphersweet-py produces the same bytes as
[paragonie/ciphersweet](https://github.com/paragonie/ciphersweet) v4. That is tested against the
upstream known-answer vectors and against a second set of vectors generated by PHP itself (see
[`tests/vectors`](https://github.com/rizalpahlevii/ciphersweet-py/tree/main/tests/vectors)).

Compatibility is only guaranteed when both sides are configured identically. To read or search
data written by PHP, use the same:

| Setting | Why it matters |
| --- | --- |
| **Key** | Every other key is derived from it. |
| **Backend** | The ciphertext prefix (`nacl:`, `brng:` or `fips:`) tells you which one wrote it. |
| **Table and column names** | They are inputs to key derivation, so `users.email` and `members.email` use different keys. |
| **Field types** | `add_integer_field` stores an 8-byte integer, not its decimal text. A type mismatch decrypts to the wrong value or fails. |
| **AAD sources** | The same columns and literals, or decryption fails. |
| **Blind index settings** | Name, transformations (in order), bit length, and fast or slow. Any difference gives different index values. |

## Naming differences

The Python API mirrors the PHP one with snake_case names:

| PHP | Python |
| --- | --- |
| `new CipherSweet($provider, new ModernCrypto())` | `CipherSweet(provider, ModernCrypto())` |
| `$row->addTextField('email')` | `row.add_text_field("email")` |
| `$row->addBlindIndex('email', new BlindIndex('idx', [], 32, true))` | `row.add_blind_index("email", BlindIndex("idx", [], 32, True))` |
| `$row->prepareRowForStorage($data)` | `row.prepare_row_for_storage(data)` |
| `$field->prepareForStorage($value)` | `field.prepare_for_storage(value)` |
| `CipherSweet\Exception\*` | `ciphersweet.*Exception` |

## Fast or slow blind indexes

`BlindIndex` defaults to a **slow** index (Argon2id for `nacl:`/`brng:`, PBKDF2 for `fips:`),
exactly like PHP's constructor. If the PHP side passed `true` as the fourth argument, pass
`fast_hash=True` or use [`FastBlindIndex`][ciphersweet.FastBlindIndex].

## Strings and bytes

PHP strings are byte strings. The built-in transformations work on bytes too, so `Lowercase`
only changes ASCII letters, as PHP's `strtolower` does. Text that is not valid UTF-8 decrypts to
`bytes` instead of `str`.

## Not yet ported

`EncryptedFile` (stream encryption of whole files) and the `FieldIndexPlanner` are not available
yet.
